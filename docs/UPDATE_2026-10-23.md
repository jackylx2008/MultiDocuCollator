# 2026-10-23 主体工作联系单附件合并与 EXE 配置

## 附件 PDF 合并

新增或修改主体工作联系单时，如填写“附件：具体问题及整改要求”，程序先生成联系单
Word/PDF 和临时附件 Word/PDF，再将附件 PDF 插入联系单 PDF 首页之后。合并成功后，
生成的文件只保留联系单 Word 和合并后的联系单 PDF，不保留临时附件 Word/PDF；
目录中原有的其他资料不受影响。

附件正文和已合并页数保存在条目目录的 `.work_contact_attachment.json` 中，以便重新扫描
时恢复页面输入内容。再次修改会替换旧的程序生成附件页；清空附件会移除这些页面。
人工添加在其后的其他页面继续保留。旧版独立附件 Word/PDF 可正常读取，并在该条目
下一次保存时按新方式合并；本次更新不批量修改历史资料。

生成和合并在暂存目录中进行。修改已有联系单时，更新前完整目录仍保存在 `_trash`。

## Windows EXE 配置

打包脚本在生成 `build/delivery/酒店需求工作联系单汇总.exe` 后，会将项目根目录现有的
`.env` 和 `common.env` 复制到交付目录。EXE 从同目录读取配置，因此本地 AI 所需的
`LLAMACPP_API_KEY` 可随本机交付目录使用。私有环境文件、EXE、日志和业务资料均由
Git 忽略，不进入仓库；复制交付目录给他人前应检查其中的私有配置。
