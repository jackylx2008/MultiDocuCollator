# 2026-11-24：归档稳定性、重复编号与日志保护

本次更新完善了酒店需求单和主体工作联系单的异常处理、编号兼容、附件写入及运行日志。

## 归档刷新与校验

- 启动时分别刷新酒店需求单和主体工作联系单；其中一个刷新失败时，另一个入口仍可使用。
- 刷新失败后，仅当已有 JSON 与 HTML 均通过校验时才继续开放对应归档；否则禁用该入口，并在控制窗口和日志中说明情况。
- 酒店需求单生成后先校验数据，再写入 JSON 和 HTML，避免无效扫描结果覆盖既有数据。

## 编号与重复资料

- 目录编号支持在数字后加一个大写字母，例如 `029A`，用于归档同一业务编号的多份已下发原件。
- Word/PDF 中的原件编号保持不变；汇总页与日志提示归档编号和原件编号。
- 扫描发现重复业务编号时保留每条资料并分配独立、稳定的内部记录 ID，在记录中显示重复提示；新增记录仍校验业务编号。

## 主体联系单附件

- 新建或修改联系单时，附件内容会追加到主 Word 正文之后并从新页开始。
- PDF 继续将附件页放在联系单 PDF 首页之后；修改时替换旧的程序生成附件页，保留其他人工附页。

## 日志与文档

- 日志统一写入 UTF-8 滚动文件；磁盘日志中的金额会遮蔽数字，控制台显示不变。
- README 已同步更新归档容错、附件处理和编号规则。
- `.gitignore` 新增忽略 `docs/` 的规则；本更新说明作为项目交付文档显式纳入版本控制。
