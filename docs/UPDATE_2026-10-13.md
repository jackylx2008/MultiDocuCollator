# 2026-10-13 主体工作联系单更新

本次更新完善了“主体工作联系单”工作流。启动 `serve_summary.py` 或 Windows EXE 后，
在服务控制窗口选择“主体工作联系单”，进入对应的 HTML 汇总页。

## 资料汇总与操作

- 扫描既有联系单及按条目整理的一级目录，在资料根目录生成 JSON 数据库和离线 HTML 汇总页。
- 整理历史资料前生成 `_backup_YYYYMMDD_HHMMSS` 和文件校验清单；每条联系单按“类别-编号-日期_主题”保存 Word、PDF、扫描件及其他资料。
- 汇总页可搜索、筛选、新增、编辑和删除条目。点击主题可查看正文与附件，点击资料按钮可将 Word/PDF 复制到 Windows 剪贴板。
- 修改条目会同步更新目录及生成文件；删除后的完整目录保存在 `_trash`。

## 正文与附件

- 新建或修改联系单时，正文用于概述问题、影响和统一整改要求；具体位置、设备、现象及整改动作填写在附件中。
- 填写附件后，在同一条目目录生成独立的附件 DOCX 和 PDF。修改附件内容会重新生成这两个文件；没有附件内容时不生成附件文件。
- 新建页可按资料目录中的 Markdown 写作规则调用本地 AI 起草正文和附件。已有长正文也可用“AI 拆分正文与附件”生成待核对的两部分草稿。
- AI 结果先在页面中预览和编辑。“接受并回填”只改变输入框；点击“保存修改”或“新增联系单”后才写入 Word/PDF。已有附件内容会保留在拆分草稿中。
- 修改原联系单时，若原 PDF 多于一页，仅替换首页，保留后续页。已有条目不会因重新扫描而自动改写正文。

本地 AI 需要服务正常运行并加载配置的模型。若接口要求认证，需通过本机私有环境变量
`LLAMACPP_API_KEY` 提供密钥；AI 不可用时仍可人工填写正文和附件。

## 编号、显示与新建入口

- 编号方式可选自动、临时或手动输入。临时序号只用于目录和 HTML 索引；新生成的 Word/PDF“资料编号”只保留类别前缀，例如“质保-”。
- 同一天的条目按类别及数字序号排列。页面加载后滚动到最近保存的条目，新增入口位于列表底部。
- 底部新增入口保持为一条紧凑表格行。点击后打开填写弹窗；类别默认“质保”，编号方式默认“临时编号”，仍可修改。
- 新建弹窗在宽屏下最大宽度为 1520 像素，基本信息横向排列，具体事项与正文并排，附件位于下方。小窗口或内容较长时，填写区可滚动，底部操作按钮保持可见。

## 保护外部修改

在 Word 等外部程序中修改资料后，先点击页面的“重新扫描刷新”。保存联系单时，程序会核对
数据库记录的文件哈希；若 Word/PDF 已在外部变化且页面尚未刷新，将拒绝覆盖并提示文件名。
修改前的完整条目目录会保存在 `_trash`，便于恢复。

## 使用与验证

```powershell
python serve_summary.py
```

在服务控制窗口选择“主体工作联系单”；使用 EXE 时操作相同。页面提供新增、编辑、删除、
搜索、资料文件复制到剪贴板，以及本地 AI 起草和拆分。

本次实现已通过 50 项单元测试。浏览器实测：在 2560×1440 分辨率下，新建弹窗为
1520×874 像素，默认空白字段与保存按钮可一屏查看；在较小窗口中，填写区出现滚动而
底部按钮仍可见。更新了 Windows 单文件 EXE。本机 EXE 和真实业务资料不纳入 Git。
